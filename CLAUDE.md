# Kaiyori (kamllistos.com) — project notes

Kaiyori (pronounced kai-YO-ri) = kai, from kaizen (改善, continuous improvement) + yori (より, "more than"): keep making the product better, step by step. Text in `site.brand.meaning`. It is a SaaS for product management that turns an idea into an MVP. **Idea stage, not built or launched**: the site says so plainly (home `#how` lead and closing "Stage: idea" line), offers early access by email only, and has no fake customers, metrics, pricing, login or signup. Built by Cam Toan Do (Cybersecurity Coordinator, Calgary). The domain stays kamllistos.com for now; GitHub org/repo names also keep the old name.
Owner has no coding background: explain plainly, keep things simple, be honest.

The **logo** is a K whose upper arm climbs in small steps (kaizen), dark `#140d0a` on an orange rounded square in both themes (`src/components/Logo.astro`, `.logo-*` in `styles.css`), next to the "Kaiyori" wordmark in heavy sans. The **whale stays the mascot** (ASCII whale in the home sky and the footer), not the logo. **Liquid glass is for navigation only**, following Apple's "Adopting Liquid Glass" guidance (developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass): glass is a functional layer for navigation and controls floating above content, used sparingly, never stacked on itself, kept legible with a scroll edge effect, with concentric corners, and with solid fallbacks for reduce-transparency and more contrast. So only the header (`.nav.glass`) and its dropdown menus (`.nav-panel.glass`) are glass. Content boxes (code boxes, changelog days, footer, the home `.mock`) are plain solid surfaces (`--pane` fill, hairline `--pane-shadow` edge); do not make them glass. The material is mostly clear (thin `--glass-tint`, 9px blur, 1px with the lens) and drawn by `::after` under the content: blur → lens (`--lens`) → saturate → `--glass-tone` (a tone curve that darkens the backdrop in dark mode and lifts it in light mode so labels always read), then a top inner glow and a faint bottom inner shadow; nav labels get a soft page-colour halo. `::before` is the specular rim: a hairline brightest on top, plus a glint that turns toward the pointer (`--glint`, one rAF per move) and drifts with scroll (`--glint-turn`, scroll-driven animation, no listener). `public/glass.js` builds one SVG lens per glass element (header and each menu): a displacement map generated on a canvas for that element's rounded rect with a squircle bezel profile (Snell's law, IOR 1.5), so content bends and magnifies toward the rim while the centre stays clear, with a faint R/G/B split at the rim; it is a `data:` PNG in an in-DOM `<feImage>` (CSP `img-src` allows `data:`), sized to the element and rebuilt only by a ResizeObserver. Chromium only (backdrop SVG filters; detected via `navigator.userAgentData`, sets `html.lens-on`). Firefox/Safari get `.glass-band`: a masked ring of extra blur under the material so the rim reads as thicker glass, with the same rim, glow and motion. Menus are more frosted (70% tint) because they reach past the scroll edge and must stay readable even where no backdrop blur is drawn. Motion (all off under `prefers-reduced-motion`): `--spring` / `--spring-soft` `linear()` easings; a hover capsule (`.nav-hl`, placed by glass.js) slides between nav items; nav items, menu links and the CTA give a little on press; menus morph out of their trigger (clip-path from the summary's box, `--tx/--ty/--tw/--th` measured in `site.js`); the theme switch has a sliding glass thumb (`.theme-thumb`, CSS `:has`, lift animation only after a click via `.moved` from `theme.js`). Never put a blur on the glass box itself (only on `::after`), or the menus' blur loses the page behind them. The **scroll edge** is `body::before`: a fixed band under the header (`--edge` high) that fades content to the page colour with a light blur and a gradient mask, and in browsers with scroll-driven animations it only fades in once the page scrolls. No scroll listener. Corners are concentric: header controls sit 8px from the header edge, so header radius 28px = 20px CTA radius + 8; menu 22px = 14px link radius + 8. `prefers-reduced-transparency: reduce` and `prefers-contrast: more` (last block of `styles.css`) make the header, menus and scroll edge solid, and more contrast draws every edge in full ink. The camtoan.me layer resets every `box-shadow` with `!important`, so glass and surface edges need `!important` too; the CSS minifier drops an unprefixed `backdrop-filter` when the `-webkit-` one sits in the same rule, so keep prefixed ones in the `@supports` block. Capsules (999px) are kept only for the header controls that must be concentric with the glass (CTA, nav items, hover highlight, theme track and thumb). Everything else is squarer and editorial, no lens: buttons outside the header 10px, the mock stage tabs one connected hairline track with 4px corners, chips, badges and status labels 3px mono tags, the footer `.updated` link plain muted text. Sizes use `clamp()` so they flow with the window; the header (`Base.astro`) is logo left, `<details>` dropdowns (Product, Resources) + Contact centre, theme toggle + "Get early access" mailto button right; dropdown close logic lives in `public/site.js`; under 860px it becomes rows. The footer is not a card: a full-width top hairline, then logo + socials from `site.links`, one row of links in four hairline-divided groups with no headings (`ul.f-links`; product, resources, company, legal; the groups stack under 560px), the **footer whale** (Cam asked for it: keep it) on its own row (an ASCII copy of the sky whale, `whaleArt(64)` in `src/skysea.ts`, 78 columns, rendered at build time, no script; `.f-whale` uses the hero's 9px cells at line-height 1.15, the 1.92 ratio `whaleArt` draws for, and shrinks with container units only to fit), and the small print with a plain "Last change <date>" link to `/changelog/` (no badge, no "days since" counter). Birds and stars live in `src/sky.ts`; the whale shape (`dorsal`, `ventral`, `body`) and clouds live in `src/skysea.ts` and are drawn as ASCII on a canvas by a small hand-written script, `src/skysea.ts` (no library, 10 fps, whole-cell steps).

## Rules
- Run `npm run build && npm run check:build` before pushing.
- Never put secrets in the repo or chat; tokens go in GitHub/Cloudflare secrets.
- Don't invent facts about the owner (certs, clients, dates).
- Commit messages are published on /changelog — write them in plain English for humans.
- Every change must show up on /changelog: one plain-English commit per meaningful change. Always.
- Use graphify to understand the codebase instead of reading files wholesale: `pip install graphifyy`, `graphify update .`, read `graphify-out/GRAPH_REPORT.md`, then `graphify explain "<name>"`. `graphify-out/` is git-ignored.
- Before the site collects anything new (form, account, analytics, cookie, newsletter, payment, new provider): update the matching pages in `src/content/legal/` first, then acknowledge the tripwire in `scripts/check-build.mjs`. Legal pages must describe what the site really does — no invented commitments.
- Public docs must never include secrets, token values, account IDs or private contact details.
