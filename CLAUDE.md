# Kaiyori (kamllistos.com) — project notes

Kaiyori (pronounced kai-YO-ri) = kai, from kaizen (改善, continuous improvement) + yori (より, "more than"): keep making the product better, step by step. Text in `site.brand.meaning`. It is a SaaS for product management that turns an idea into an MVP. **Not launched yet**: the site says early access / in development, with no fake customers, metrics, pricing, login or signup. Built by Cam Toan Do (Cybersecurity Coordinator, Calgary). The domain stays kamllistos.com for now; GitHub org/repo names also keep the old name.
Owner has no coding background: explain plainly, keep things simple, be honest.

## Where things live
- Text: `src/site.ts` · About lives on camtoan.me (`/about` redirects there)
- The old security feature database (`/search/`, `/glossary/*`, `/api/glossary`) was removed; `public/_redirects` sends those URLs to `/products/` (launch checklist, rules pack, review on Gumroad). Home (`src/pages/index.astro`) is the SaaS landing page: ASCII sky, bare hero copy ("Idea to MVP. Even better.", early-access mailto CTA) beside an illustrative product mock (`.mock`, a solid card, labelled as not real data: one example project, "Late-invoice reminders"; its five stages Idea/Spec/Build/Secure/Ship are accessible tabs run by `public/mock.js`, Spec shows without JS, Build tasks can be ticked, and a dashed arc plus "Plan v2 from feedback" loops Ship back to Idea), `#how` staircase of the same five stages ending in a "then round again" loop line, split "why" list and a closing CTA. Whale swims in the lower hero band. On phones (≤480px) the header is two rows and the theme toggle is hidden (theme follows OS)
- Design: same language as camtoan.me (mono + heavy sans, hairline borders, grid paper, one orange accent, Auto/Light/Dark toggle via `public/theme.js`) in `src/styles.css`. The **logo** is a K whose upper arm climbs in small steps (kaizen), dark `#140d0a` on an orange rounded square in both themes (`src/components/Logo.astro`, `.logo-*` in `styles.css`), next to the "Kaiyori" wordmark in heavy sans. The **whale stays the mascot** (ASCII whale in the home sky and the footer), not the logo. **Liquid glass is for navigation only**, following Apple's "Adopting Liquid Glass" guidance (developer.apple.com/documentation/technologyoverviews/adopting-liquid-glass): glass is a functional layer for navigation and controls floating above content, used sparingly, never stacked on itself, kept legible with a scroll edge effect, with concentric corners, and with solid fallbacks for reduce-transparency and more contrast. So only the header (`.nav.glass`) and its dropdown menus (`.nav-panel.glass`) are glass. Content boxes (cards, tiles, code boxes, changelog days, footer, the home `.mock`) are plain solid surfaces (`--pane` fill, hairline `--pane-shadow` edge); do not make them glass. The glass is drawn by `::after` under the content (blur → lens → saturate on the backdrop, tint from `--glass-fill`, sheen, inner rim) and `::before` is a specular ring that turns toward the pointer (`--glint`). `public/glass.js` builds one SVG lens, for the header only, and passes it in as `--lens` (Chromium only; Firefox/Safari get the same CSS as frosted glass; no library, CSP unchanged). The menus share the header's material without their own lens and open with a small transform-only grow, so they read as the header opening. Never put a blur on the glass box itself (only on `::after`), or the menus' blur loses the page behind them. The **scroll edge** is `body::before`: a fixed band under the header (`--edge` high) that fades content to the page colour with a light blur and a gradient mask, and in browsers with scroll-driven animations it only fades in once the page scrolls. No scroll listener. Corners are concentric: header controls sit 8px from the header edge, so header radius 28px = 20px CTA radius + 8; menu 22px = 14px link radius + 8. `prefers-reduced-transparency: reduce` and `prefers-contrast: more` (last block of `styles.css`) make the header, menus and scroll edge solid, and more contrast draws every edge in full ink. The camtoan.me layer resets every `box-shadow` with `!important`, so glass and surface edges need `!important` too; the CSS minifier drops an unprefixed `backdrop-filter` when the `-webkit-` one sits in the same rule, so keep prefixed ones in the `@supports` block. Chips and badges are plain capsules, no lens. Sizes use `clamp()` so they flow with the window; the header (`Base.astro`) is logo left, `<details>` dropdowns (Product, Resources) + Contact centre, theme toggle + "Get early access" mailto button right; dropdown close logic lives in `public/site.js`; under 860px it becomes rows. The footer is a big four-column link grid (Product, Resources, Company, Legal) with socials from `site.links`, an ASCII copy of the sky whale on its own row above the copyright and `.updated` badge (`whaleArt(90)` in `src/skysea.ts`, rendered at build time, no script; `.f-whale` uses the hero's 9px cells at line-height 1.15, the 1.92 ratio `whaleArt` draws for, and shrinks with container units only to fit its 98 columns) (4 → 2 → 1 columns). Birds and stars live in `src/sky.ts`; the whale shape (`dorsal`, `ventral`, `body`) and clouds live in `src/skysea.ts` and are drawn as ASCII on a canvas by a small hand-written script, `src/skysea.ts` (no library, 10 fps, whole-cell steps).

## Rules
- Run `npm run build && npm run check:build` before pushing.
- Never put secrets in the repo or chat; tokens go in GitHub/Cloudflare secrets.
- Don't invent facts about the owner (certs, clients, dates).
- Commit messages are published on /changelog — write them in plain English for humans.
- Every change must show up on /changelog: one plain-English commit per meaningful change. Always.
- Use graphify to understand the codebase instead of reading files wholesale: `pip install graphifyy`, `graphify update .`, read `graphify-out/GRAPH_REPORT.md`, then `graphify explain "<name>"`. `graphify-out/` is git-ignored.
- Before the site collects anything new (form, account, analytics, cookie, newsletter, payment, new provider): update the matching pages in `src/content/legal/` first, then acknowledge the tripwire in `scripts/check-build.mjs`. Legal pages must describe what the site really does — no invented commitments.
- Public docs must never include secrets, token values, account IDs or private contact details.
